## 1. 設計方針

| # | 方針 | 理由 |
|---|---|---|
| 1 | **サーバを立てない。`index.html` を開くだけで動く** | 庁内PCへのランタイム（Python / Node.js）導入可否が不明だった。Edge だけで完結すれば導入調整が不要になる |
| 2 | **外部ネットワークに一切アクセスしない** | 扱うのが職員と扶養親族の個人情報であるため。CDN参照も行わず、外部ライブラリは `vendor/` に同梱する |
| 3 | **業務ロジックを DOM から切り離す** | 抽出・和暦・年齢の計算を純粋関数に閉じ込め、ブラウザなしで自動テストできるようにする |
| 4 | **運用で変わる値をコードから追い出す** | 除外する身分・列名・年度範囲は `assets/config.js` に集約し、改修せずに運用側で直せるようにする |
| 5 | **帳票のレイアウトを絶対寸法（mm）で持つ** | 記入例PDFの罫線座標をそのまま再現するため。相対レイアウトでは印刷結果が環境で揺れる |
| 6 | **ビルド処理を持たない** | 配布が「フォルダをコピーするだけ」で完結する。トランスパイル・バンドルの環境を庁内に用意しなくてよい |

### 1.1 方針から導かれる制約

方針1・6の帰結として、次の技術選択は**採用できない**。改修時も踏襲すること。

| 使えないもの | 理由 |
|---|---|
| ES モジュール（`import` / `export`、`<script type="module">`） | `file://` では CORS 制限により読み込めない |
| `fetch()` / `XMLHttpRequest` によるローカルファイル読み込み | 同上。ファイル読み込みは `<input type="file">` ＋ `FileReader` のみ |
| npm パッケージの直接 import、バンドラ前提の記法 | ビルド処理がないため。外部ライブラリは配布可能な単一ファイルを `vendor/` に置く |
| Web フォント（Google Fonts 等） | 外部アクセスになる。システムフォントのみ使用する |

## 4. モジュール構成

### 4.1 依存関係

```
  version.js ── 定数のみ（依存なし）
  config.js  ── 設定のみ（依存なし）
  core.js    ── 業務ロジック（依存なし・DOMに触れない）
       ▲
       │
  csv.js     ── core.formatIso を使用
  render.js  ── 依存なし（DOMに触れず、HTML文字列を返すだけ）
       ▲          ▲
       │          │
  app.js ────────┴──── XLSX / Config / Core / Render / Csv / window.APP_VERSION を使用
                        唯一 DOM を操作する層
```

**依存の向きは一方向**で、`core.js` `render.js` `csv.js` は `app.js` を知らない。
この分離により、業務ロジックはブラウザなしでテストできる。

### 4.2 読み込み順（`index.html` 末尾）

```html
<script src="assets/version.js"></script>
<script src="vendor/xlsx.full.min.js"></script>
<script src="assets/config.js"></script>
<script src="assets/core.js"></script>
<script src="assets/render.js"></script>
<script src="assets/csv.js"></script>
<script src="assets/app.js"></script>
```

`csv.js` は `Core` を参照するため **`core.js` より後**、`app.js` は全てを使うため**最後**に置く。
スクリプトを追加する場合はこの順序規則を守ること。

### 4.3 モジュール定義の書き方（UMD）

`config.js` `core.js` `render.js` `csv.js` は、ブラウザとNodeの両方から読めるよう
次の形をとる。ブラウザではグローバル（`window.Core` 等）に、Nodeでは `module.exports` になる。

```js
(function (root, factory) {
  var api = factory();
  if (typeof module === 'object' && module.exports) module.exports = api;
  else root.Core = api;
})(typeof self !== 'undefined' ? self : this, function () {
  'use strict';
  /* ... */
  return { /* 公開する関数 */ };
});
```

他モジュールに依存する `csv.js` だけは、依存の解決を factory の外で行う。

```js
(function (root, factory) {
  var CoreDep = (typeof module === 'object' && module.exports) ? require('./core.js') : root.Core;
  var api = factory(CoreDep);
  /* ... */
})(/* ... */, function (Core) { /* ... */ });
```

`app.js` は DOM 専用でテスト対象外のため、UMDではなく即時実行関数（IIFE）で書く。
`version.js` は定数2つのみのため、`window` への代入だけとする。

## 5. データ構造

### 5.1 取込直後（生データ）

SheetJS の `sheet_to_json` が返すオブジェクトの配列。
**キーは Excel の見出し行の文字列そのまま**（例: `row['番号']`、`row['temp_kingaku']`）。

```
RosterRow = { '番号': 1000, '氏名': '志田　一朗', '在職': 1, '身分': '正職員', ... }
DepRow    = { 'number': 1000, 'year': 2026, 'kanji': '志田　尚子', 'birthday': Date, ... }
```

列名に直接依存するのは `config.js` の `columns` と、それを参照する `core.extract()` のみ。

### 5.2 抽出結果（`Core.extract()` の戻り値）

```
Result {
  sheets   : Staff[]     印刷対象。1要素 = 調査書1枚 = 職員1人
  errors   : Message[]   データ不備。印刷対象から除外したもの
  warnings : Message[]   要確認。印刷対象外にした理由や重複の通知
  infos    : Message[]   お知らせ。対象に含めたが判断を仰ぎたいもの
  stats    : Stats       件数の集計
  fiscal   : FiscalParams 年度から導出したパラメータ
}

Staff {
  no          : number   職員番号（名簿「番号」）
  name        : string   職員氏名
  shozokuCd   : number   所属コード（並び順に使用）
  shozokuName : string   所属名（印字・絞り込みに使用）
  kakariCd    : number   係コード（並び順に使用）
  deps        : Dep[]    対象扶養親族（temp_jyun 順）
}

Dep {
  row         : number   扶養データ上の行番号（メッセージ表示用）
  name        : string   扶養親族氏名
  birth       : Date     生年月日（UTC基準）
  birthWareki : string   和暦略記（例 "S35.3.1"）
  age         : number   基準日時点の満年齢
  jyun        : number   temp_jyun（並び順）
  kingaku     : number   扶養手当月額（CSV出力のみで使用。様式には印字しない）
}

Message { src: '名簿'|'扶養', row: number|null, msg: string }

Stats {
  rosterRows, depRows          取り込んだ行数
  activeStaff                  在職者として抽出できた人数
  excludedByStatus             身分により除外した人数
  unknownStatus                未知の身分の種類数
  targetDeps                   対象扶養親族の延べ人数

  fy         : number   対象年度（西暦4桁）
  baseDate   : Date     基準日 = FY年6月1日

  heading    : string   様式の見出し（例「扶養親族（6.1時点　扶養手当対象者）」）

```

### 5.3 画面の状態（`app.js` の `state`）

```
state {
  roster   : RosterRow[]        取り込んだ名簿データ
  deps     : DepRow[]           取り込んだ扶養データ
  result   : Result             直近の抽出結果
  selected : { [職員番号]: boolean }   印刷対象のチェック状態
}
```

`selected` は**未登録なら選択済みとみなす**（`state.selected[no] !== false`）。
抽出直後は全件が印刷対象になり、外したものだけが `false` として記録される。

## 6. 日付の設計

日付処理は本システムで最も誤りやすい箇所のため、設計を固定する。

### 6.1 内部表現は UTC 基準の `Date` に統一する

`Core.ymd(y, m, d)` が返す `Date.UTC` ベースの値のみを使い、
読み出しは必ず `getUTCFullYear()` 系で行う（`Core.parts()` が担当）。

**理由**: ローカルタイムゾーンで `new Date(1960, 2, 1)` を作ると、時差により
日付比較や年齢計算が1日ずれる可能性がある。基準日との大小比較（生年月日上限）を
安全に行うため、内部では時差の概念を持ち込まない。

### 6.2 入力の3形態を1つの関数で吸収する

`Core.toDate(v)` が次を受け付け、それ以外と空欄は `null` を返す。

| 入力 | 由来 | 変換 |
|---|---|---|
| `Date` | 扶養データの `birthday`（SheetJS が日付型として返す） | **ローカルの年月日を読み取り UTC で作り直す**（下記注意） |
| 数値 | 名簿データの `生年月日` `採用日` `退職日` | Excelシリアル値（1900日付システム／基準 1899-12-30）として変換 |
| 文字列 | CSV等に切り替わった場合の保険 | `YYYY-MM-DD` `YYYY/M/D` `YYYY年M月D日` を解釈 |

> **注意**: SheetJS の `cellDates: true` はローカル時刻の `Date` を返す。
> そのまま UTC で読むと日付がずれるため、`getFullYear()` 等**ローカルの値**で
> 読み取ってから `ymd()` で作り直している（`core.js` の該当行にコメントあり）。
> ここを「UTCで読む」に変えると日本時間（UTC+9）では日付が前日にずれる。

### 6.3 和暦変換

`Core.eraOf(dt)`（内部関数）が元号テーブル `ERAS` を新しい順に走査し、
最初に該当した元号を返す。テーブルは改元日を境界として持つ。

| 元号 | 記号 | 開始日 |
|---|---|---|
| 令和 | R | 2019-05-01 |
| 平成 | H | 1989-01-08 |
| 昭和 | S | 1926-12-25 |
| 大正 | T | 1912-07-30 |
| 明治 | M | 1868-09-08 |

これを 2つの公開関数が使い分ける。**元年の表記が異なる**点に注意。

| 関数 | 用途 | 元年の表記 | 例 |
|---|---|---|---|
| `formatWareki(dt)` | **様式の生年月日欄** | `1`（`R1`） | `1960-03-01` → `S35.3.1` |
| `fiscalYearLabel(fy)` | **画面の年度プルダウン** | `元` | `2026` → `令和8年度`、`2019` → `令和元年度` |

様式は既存の運用に合わせた略記、プルダウンは人が読む一覧としての自然さを優先している。
**どちらかに合わせて統一してはならない**（テストで両方の挙動を固定している）。

## 7. 抽出処理の設計（`Core.extract()`）

仕様書3章の抽出要件を実装する唯一の関数。DOM に触れず、入力と設定だけで結果が決まる。

### 7.1 処理の流れ

```
入力: roster[], deps[], fy, config
  │
  ├─ STEP0  fiscalParams(fy) で基準日・生年月日上限・見出しを導出
  │
  ├─ STEP1  名簿を走査して在職者の索引 staffByNo を作る
  │           ・番号が数値でない            → errors に追加してスキップ
  │           ・在職 ≠ 1                    → nonTarget に理由を記録してスキップ
  │           ・身分が excludedStatuses     → nonTarget に理由を記録してスキップ（件数計上）
  │           ・身分が未知（既知リスト外）  → infos に追加し、対象には含める
  │           ・職員番号の重複              → warnings に追加し、先勝ちで無視
  │
  ├─ STEP2  扶養データを走査して対象扶養親族を staffByNo[no].deps に積む
  │           ・year ≠ FY / teate ≠ 1 / kingaku ≤ 0  → 静かにスキップ（正常な対象外）
  │           ・birthday が読めない                   → errors に追加してスキップ
  │           ・birthday > 生年月日上限               → 静かにスキップ（正常な対象外）
  │           ・番号が数値でない                      → errors に追加してスキップ
  │           ・名簿に該当職員がいない                → warnings（nonTarget の理由を添える）
  │
  ├─ STEP3  対象扶養親族が1名以上の職員だけを sheets に採用
  │           ・同名・同生年月日の重複を検出 → warnings（集約はせず全件残す）
  │           ・deps を temp_jyun 順（同値なら行順）に整列
  │           ・deps が上限（既定9名）超    → warnings に追加し sheets から除外
  │
  └─ STEP4  sheets を 所属CD → 係CD → 職員番号 の順に整列
```

### 7.2 設計上の判断

| 判断 | 内容 | 理由 |
|---|---|---|
| **「静かにスキップ」と「警告」を区別する** | 年度違い・`teate=0`・年齢未満などは正常な対象外としてメッセージを出さない。名簿に無い・日付が読めない等だけを通知する | 正常な対象外まで通知すると件数が膨れ、本当に見るべき警告が埋もれる |
| **未知の身分は対象に含める** | 除外リストにも既知リストにも無い身分は、対象に含めたうえで `infos` に出す | 逆（除外）にすると、気づかないうちに対象者が漏れる。取りこぼしより過剰抽出の方が発見しやすい |
| **対象外の理由を記録する（`nonTarget`）** | STEP1でスキップした職員の理由を保持し、STEP2で「名簿に無い」と誤報しないようにする | 「名簿にありません」とだけ出ると、実際は身分で除外した職員の調査に時間を取られる |
| **重複を集約しない** | 同名・同生年月日の扶養親族は警告を出しつつ全件残す | データ不備か実在かをシステムが判断できない。人が見て判断できるよう情報を落とさない |
| **上限超過は印刷対象外にする** | 1ページに収まらない職員は出力せず警告する | 収まらないまま印刷すると、欄が足りないことに気づかず配布してしまう |

## 8. 帳票出力の設計

### 8.1 寸法の持ち方（`form.css`）

記入例PDFから抽出した罫線座標（96dpi のCSSピクセル）を **mm に換算して固定値で持つ**。

```
.sheet        210mm × 297mm の position:relative コンテナ（＝A4用紙1枚）
  .body       position:absolute  left 19.98mm / top 25.35mm / width 170.23mm
              └ 内部は通常フロー。要素間は margin-top で記入例どおりの間隔を再現
  .tblD       position:absolute  top 262.94mm（担当者確認欄。用紙下端に固定）
```

**本文を通常フロー、担当者確認欄だけ絶対配置**にしているのが要点。
扶養親族が増えて表Aの行数が増えると、表B以降は自然に下へ送られるが、
担当者確認欄は用紙下端に留まる（仕様書4.10のとおり）。

列幅は `<colgroup>` に mm 値で指定し、行高は `td { height: ... }` で固定する。

### 8.2 検証方法

`docs/mock/form-mock.html` が記入例PDFと同じ内容の静的モックである。
レイアウトを変更したら、これを PDF 化して記入例PDFと重ね合わせ、
主要要素の位置ずれが 0.5mm 以内に収まることを確認する（仕様書4.12）。

### 8.3 印刷時の切り替え

```css
@media print {
  #ui { display: none !important; }   /* 操作画面を隠す */
  .sheet { break-after: page; }       /* 1枚＝1ページ */
  .sheet:last-child { break-after: auto; }
}
```

`ui.css` と `form.css` の両方に印刷用の指定があるが、**役割を分けている**。
`ui.css` は操作画面を隠すこと、`form.css` は用紙の改ページを担当する。

### 8.4 組版（`render.js`）

`Render.sheets(staffList, fiscal)` が調査書全体のHTML文字列を返し、
`app.js` が `#sheets` に流し込む。DOM APIは使わず文字列連結で組み立てる。

**公開API**

| 関数 | 戻り値 |
|---|---|
| `Render.sheets(staffList, fiscal)` | 調査書全体（職員ごとの `.sheet` を連結） |
| `Render.sheet(staff, fiscal)` | 調査書1枚 |
| `Render.esc(s)` | HTMLエスケープ。**氏名・所属名など外部データを埋め込む箇所では必ず通す** |

内部関数 `tableA(deps)` が表Aを組み立てる。**データ行数 = `deps.length + 1`**（予備1行）。

氏名とヘッダの均等割付は CSS の `.just`（`text-align: justify` + `text-align-last: justify`）で行う。
文字数によって字間が変わるため、固定の字送りにはしない。

### 9.2 主な要素と役割

| 要素ID | 種別 | 役割 |
|---|---|---|

| `btnRun` | button | 取込と抽出の実行 |
| `stats` / `msgs` | div | 件数タイル／エラー・警告・お知らせ |

### 9.3 処理の流れ

```
[年度選択] [ファイル選択]
      │  change → ready()          … 3つ揃うまで btnRun を無効化
      ▼
[読み込んで抽出する] btnRun
      │  run()
      │   ├ readSheet() ×2        … FileReader → XLSX.read → sheet_to_json
      │   ├ checkColumns() ×2     … 必須列の存在確認（無ければ例外）
      │   ├ Core.extract()        … 抽出
      │   └ renderStats / renderMsgs / renderList
      ▼
[所属で絞り込み / チェック操作]       … drawRows() で再描画
      │
      ├─[一覧をCSV出力] btnCsv → exportCsv()  … visibleSheets() を Csv.build → download
      │
      ▼
[印刷プレビューを作る] btnPreview
      │  preview() … chosen() を Render.sheets して #sheets に流し込む
      ▼
[印刷する] btnPrint → window.print()
```

### 9.4 「表示中」と「選択」の使い分け

| 操作 | 対象 | 実装 |
|---|---|---|
| 印刷 | チェックが入っている職員（所属の絞り込みとは無関係） | `chosen()` |
| CSV出力 | 表に表示されている職員（所属の絞り込みを反映、チェックは無関係） | `visibleSheets()` |

CSVは「名簿・監査用の一覧」であり印刷対象の選択とは目的が異なるため、あえて連動させていない。
画面上にもその旨を明記している。

## 10. メッセージ設計

メッセージは3段階に分け、色とアイコンで区別する（`ui.css` の `.msg.err` / `.warn` / `.info`）。

| 区分 | 意味 | 利用者に求める行動 | 主な発生箇所 |
|---|---|---|---|
| **エラー** | データ不備。印刷対象から除外した | 元データの修正 | 結合キーが数値でない、`birthday` が読めない |
| **警告** | 処理は続けたが確認してほしい | 内容の確認 | 名簿に該当職員なし、身分による除外、職員番号重複、扶養親族の重複、上限超過 |
| **お知らせ** | 対象に含めたが判断を仰ぎたい | 設定の見直し | 未知の身分を検出 |

`Message.row` は**元データの行番号**（見出し1行を含む1始まり）を入れる。
`core.js` 側で `i + 2` として算出しており、Excelの行番号と一致するため、
利用者が元ファイルの該当行をすぐ開ける。

取込自体に失敗した場合（ファイルが壊れている、必須列がない等）は
`fail()` がエラー枠に例外メッセージを表示し、以降のセクションを隠す。

## 11. 設定設計（`assets/config.js`）

改修せずに運用側で変更できる項目を集約している。変更後はブラウザの再読み込み（Ctrl+F5）で反映される。

| 設定 | 型 | 既定値 | 用途 |
|---|---|---|---|
| `excludedStatuses` | string[] | パート（時間額）／パート（日額） | 対象外とする身分 |
| `knownIncludedStatuses` | string[] | 正職員 | 対象に含めることが確認済みの身分 |
| `maxDependentsPerSheet` | number | 9 | 1枚に収まる扶養親族の上限 |
| `fiscalYearRange` | {before, after} | {2, 3} | 年度プルダウンの表示範囲 |
| `sheetNames` | {roster, deps} | {null, null} | 読み込むシート名（null は先頭シート） |
| `columns` | object | 仕様書5.2/5.3 のとおり | 列名の対応表 |

### 11.1 身分の突合方法

`excludedStatuses` との比較は `Core.normalizeKey()`（NFKC正規化＋空白除去）を通して行う。
これにより `パート（時間額）` `パート(時間額)` `ﾊﾟｰﾄ(時間額)` ` パート （ 時間額 ） ` がすべて一致する。

**理由**: 名簿データ上の正確な表記（括弧が全角か半角か等）が未確認のため。
表記が判明しても正規化は残す（人事システム側の改修で表記が揺れても壊れないため）。

### 11.2 列名対応表

人事給与システムの出力見出しが変わった場合、**`columns` の値だけを直せば動く**。
`core.js` 本体は列名を直接持たない。

## 14. 配布・バージョン管理設計

### 14.1 バージョンの持ち方

`assets/version.js` の2定数が唯一の情報源で、`app.js` の `showVersion()` が
画面右上のバッジ（ホバーで更新日）と最下部に表示する。

```js
window.APP_VERSION = '1.5.0';
window.APP_VERSION_DATE = '2026-09-15';
```

**ビルド処理がないため自動採番できず、手動更新とする。**
`package.json` の `version` も同じ値に合わせる。

### 14.2 なぜバージョン表示が必要か

サーバを介さずフォルダをコピーする配布方式のため、
**新しい版を配ったつもりでも相手の手元は古いコピーのまま**という事象が実際に発生した。
画面上の番号を見比べれば「配布物が古い」のか「同じ版でも挙動が違う」のかを切り分けられる。

### 14.3 配布手順

1. `assets/version.js` の番号と日付を更新する（`package.json` も合わせる）
2. 最新の内容でフォルダを作り直す（古いファイルが残らないようにする）
3. ZIP化してUSB等で配る
4. 受け取る側は**古いフォルダを削除してから**展開する
5. 画面右上の番号が想定どおりか確認する。変わらない場合は `Ctrl + F5`
   （`file://` のページもブラウザにキャッシュされることがある）

## 15. 既知の制約と拡張余地

| # | 制約 | 理由 | 拡張する場合 |
|---|---|---|---|
| 1 | 対象扶養親族が10名以上の職員は印刷対象外（警告のみ） | 2ページ分割を実装していない。18歳以上が10名以上は実務上想定しにくい | 表Aを分割し2枚目を出力する。表B〜Dの配置ルールを決める必要がある |
| 2 | 続柄を印字しない | `zokugara` のコード表が未入手 | コード表を入手して `config.js` に対応表を持たせる |
| 3 | 添付書類を印字しない | 様式に該当欄がなく、案内は通知文書側の役割 | 仕様書7章に判定ルールを整理済み。ただし扶養データに判定材料がない（仕様書7.7） |
| 4 | 在職判定が `在職 = 1` のみ | `在職` 列の取り得る値が未確認 | `採用日` / `退職日` による基準日時点の判定を追加する |
| 5 | 共済組合の被扶養者資格確認調査書は対象外 | 本フェーズのスコープ外。根拠が別団体の制度 | 様式を入手すれば `render.js` に並べて実装できる |
| 6 | 進捗管理・回収後の処理を持たない | スコープ外 | 別システムとして設計すべき範囲 |

### 15.1 改修時に壊しやすい箇所

| 箇所 | 注意 |
|---|---|
| `toDate()` のDate分岐 | SheetJS のローカル時刻対応（6.2）。UTCで読むと日付がずれる |
| 元年の表記 | 様式は `R1`、プルダウンは `令和元年度`。統一してはならない（6.3） |
| `form.css` の mm 値 | 記入例PDFの実測値。変更したら必ず重ね合わせ検証（8.2） |
| スクリプトの読み込み順 | `csv.js` は `core.js` の後、`app.js` は最後（4.2） |
| `.gitignore` の `*.xlsx` | 実データ除外のための指定。`test/fixtures/` は明示的に追跡対象へ戻してある |
