# 扶養親族資格確認調査書（扶養手当）印刷システム 仕様書

- バージョン: v1.4（確定・実装済）
- 作成日: 2026-09-14
- ステータス: **仕様確定**。様式・入力データ・抽出条件とも確定。残件は9章のとおり（実装の着手を妨げない）。

## 1. 背景・目的

### 1.1 根拠資料

本システムは、**陸前高田市**（市レベル）の下記内部通知に基づく事務を支援する。

| 項目 | 内容 |
|---|---|
| 文書名 | 令和８年度被扶養者及び扶養親族資格確認調査の実施について（通知） |
| 文書番号 | 陸高総号外 |
| 日付 | 令和８年８月３日 |
| 発出 | 陸前高田市 総務部総務課長 |
| 宛先 | 各部課等の長 |

上記は市の**内部通知（事務連絡）**であり、条例・規則ではない。

### 1.2 未確認事項（法令根拠）

扶養手当そのものの根拠規定（陸前高田市職員の給与に関する条例の扶養手当に係る条文、
及び同施行規則における扶養親族の届出・認定手続の条文）は、**本セッションから
例規集（条例規則/現行フォルダ）を参照できないため未確認**である。推測での引用は行わない。

仕様確定前に、以下を例規集で確認し本書に条文番号とノート名を追記すること。

- 陸前高田市（市）: 職員の給与に関する条例 — 扶養手当の支給要件・扶養親族の範囲
- 陸前高田市（市）: 同施行規則等 — 扶養親族届・認定・資格確認の手続
- 参考: 国の一般職の職員の給与に関する法律（国レベル）の扶養手当規定との異同

なお、別紙１の「被扶養者資格確認調査」は**共済組合（市とは別の団体）**の制度であり、
市の扶養手当とは根拠が異なる。混同しないこと。本システムの対象は**扶養手当のみ**。

### 1.3 目的

職員係が、扶養手当の資格確認調査に用いる「扶養親族確認調査書」を、
人事給与システムから出力した対象者データをもとに**事前印字した状態で人数分印刷**できるようにする。

## 2. スコープ

### 2.1 対象

- 扶養手当に係る「**扶養親族確認調査書**」の帳票印刷
- 対象者の抽出（基準日・生年月日による絞り込み）
- 調査書への職員情報・扶養親族情報の事前印字

### 2.2 対象外（本フェーズ）

- 共済組合の「被扶養者資格確認調査書」の印刷
- 提出状況の進捗管理・督促
- 回収後の審査結果の登録・返納処理
- 人事給与システムへの書き戻し
- **添付書類チェックリストの印字**（7章の理由により本フェーズでは行わない）

## 3. 対象者抽出要件

### 3.1 年度パラメータ

対象年度を西暦4桁 `FY` で指定する（令和8年度 = 2026、令和9年度 = 2027）。

```
基準日       = date(FY, 6, 1)          -- 抽出・年齢算出の基準日
生年月日上限 = date(FY - 18, 4, 1)
```

| 年度 | FY | 生年月日上限 | 通知の表記 |
|---|---|---|---|
| 令和８年度 | 2026 | 2008-04-01 | 平成２０年４月１日以前の出生者 |
| 令和９年度 | 2027 | 2009-04-01 | 平成２１年４月１日以前の出生者 |

基準日は通知【別紙】２⑴のとおり **FY年6月1日**（令和8年度なら令和8年6月1日）とする。
抽出・年齢算出とも同日を用いる。

`FY - 18` で毎年度自動計算されるため、年度を切り替えるだけで運用できる。
生年月日上限をハードコードしてはならない。

なお、対象は「子」に限らず**扶養親族全員**（配偶者・父母等を含む）である。
通知【別紙】２⑴も「平成２０年４月１日以前の出生者」と親族種別を限定していない。

### 3.2 抽出手順

```
STEP1  在職者の抽出（名簿データ）
         名簿.在職 = 1
     AND 名簿.身分 NOT IN (除外身分リスト)      -- 既定: パート（時間額）／パート（日額）

STEP2  対象扶養親族の抽出（扶養データ）
         扶養.year         = FY
     AND 扶養.teate        = 1
     AND 扶養.temp_kingaku > 0          -- 0 および NULL は対象外
     AND 扶養.birthday    <= 生年月日上限
         -- 扶養.month は業務上の意味を持たないため抽出条件に使用しない

STEP3  結合
         扶養.number = 名簿.番号
         （STEP1 の在職者に紐づく扶養親族のみを印刷対象とする）

STEP4  並び順
         名簿.所属CD, 名簿.係CD, 名簿.番号, 扶養.temp_jyun
```

### 3.3 除外・警告の扱い

| ケース | 扱い |
|---|---|
| 扶養データに存在するが名簿に該当 `番号` がない | **警告一覧に出力**（退職者の残データ等の可能性）。印刷対象外 |
| 名簿の `身分` が除外身分リストに該当 | 対象外（正常。件数のみ表示） |
| 名簿に在職者として存在するが対象扶養親族が0件 | 印刷対象外（正常。件数のみ表示） |
| `teate` = 1 だが `temp_kingaku` = 0 | 対象外（正常） |
| `birthday` が空 | **エラー一覧に出力**。印刷対象外 |

### 3.4 除外する身分

名簿データの **`身分`** 列で判定する。次の身分は扶養手当の対象外であり、印刷対象から除外する。

| 除外する身分 |
|---|
| パート（時間額） |
| パート（日額） |

- 除外リストは**設定値として外出し**し、コードに埋め込まない（身分の新設・改称に対応するため）
- 名簿上の正確な表記（括弧が全角か半角か等）は未確認のため、比較時は
  **全角／半角の括弧・英数字・スペースを正規化**したうえで突合する
- 除外リストに一致しない未知の身分が現れた場合は、**対象に含めたうえで情報一覧に出力**し、
  職員係が除外要否を判断できるようにする（意図しない取りこぼしを防ぐため）
- `区分名` 列にも同様の値が入り得るが、判定には **`身分` 列のみ**を使用する

### 3.5 補足

- `month` 列は業務上の意味を持たない（確認済）。抽出条件・レコード選択のいずれにも使用しない。
  同一職員に同一扶養親族のレコードが複数現れた場合は 5.5 のとおり警告一覧に出力する。
- `在職` 列が取り得る値（1 以外に何があるか）は未確認。`在職 = 1` を在職者として扱う。
  基準日時点の在職で厳密に判定する必要が生じた場合は `採用日` / `退職日` による判定を追加する。

### 4.7 氏名・見出しの均等割付

記入例では、氏名およびヘッダ文字がセル幅いっぱいに**均等割付（分散配置）**されている。

- ヘッダ「名　　　前」: セル 75.5–188.8 に対し「名」が x84.8、「前」が x165.0
- データ「志田　尚子」: 「志 田」が x84.8–117.6、「尚 子」が x147.2–179.8

実装では CSS の `text-align: justify` + `text-align-last: justify`（または文字間隔調整）で再現する。
氏名の文字数（2文字〜）によって字間が変わるため、固定の字送りではなく均等割付として実装すること。

### 4.8 生年月日の和暦変換

記入例では `S35.3.1` と印字されている（元データ `1960-03-01`）。

- 形式: `元号記号` + `年.月.日`（**ゼロ埋めなし**）
- 元号記号: M（明治）／T（大正）／S（昭和）／H（平成）／R（令和）
- 元年は **`1`** と表記する（`R1` 形式。「元」は使わない）

改元日（S→H: 1989-01-08、H→R: 2019-05-01）を正しく扱う変換関数を実装する。

### 4.9 年齢の算出

**基準日（FY年6月1日）時点の満年齢**を算出し、数値のみ印字する（「才」は様式側の固定文字）。

```
年齢 = 基準日の年 - birthday の年 - (基準日の(月,日) < birthday の(月,日) ? 1 : 0)
```

記入例の検証: `1960-03-01` / 基準日 `2026-06-01` → 66 才（記入例と一致）。

### 4.10 表Aの行数

**データ行数 = 対象扶養親族の人数 + 予備1行。**

- 対象者0名の職員は、そもそも印刷対象外（3.2 STEP3）
- 対象者1名なら2行（記入例と一致）、3名なら4行
- 行が増えた分、表B以降の要素は下方向にそのまま送られる（表Dのみ用紙下端に固定）

1ページに収まる上限:

```
表A末尾(351.0px) から 表D上端(993.8px) までの余白 = 332.7px
行高 37.7px → 追加可能 8行
→ データ行は最大 10 行、すなわち対象扶養親族 9名 まで1ページに収まる
```

対象者が10名以上になった場合は**警告一覧に出力**し、当該職員は手作業対応とする
（18歳以上の扶養親族が10名以上という事例は実務上想定しにくいため、
 2ページ分割の実装は行わない）。

## 5. 入力データ仕様

### 5.1 方式

人事給与システム等から出力した **Excel（.xlsx）2ファイル**を本システムに取り込む。

| # | ファイル | 役割 |
|---|---|---|
| 1 | 名簿データ | 在職判定、職員の氏名・所属・職名の取得 |
| 2 | 扶養データ | 扶養親族の抽出、氏名・生年月日・続柄の取得 |

- ヘッダ行（1行目）の**列名で対応付ける**。列順・列数の増減に依存しない
- CSV 形式での提供に切り替わった場合にも対応できるよう、
  読み取り層を Excel / CSV で差し替え可能な構造にする
  （CSV の場合は CP932 / UTF-8(BOM付) を自動判別）

### 5.2 名簿データ（41列）

結合キー・判定・印字に使う列は以下。その他の列（PASS、社保、Mail、住所、電話、
緊急時連絡先等）は**個人情報保護の観点から取り込まない**。

| 列名 | 型 | 用途 | 備考 |
|---|---|---|---|
| `番号` | 数値 | **結合キー** | 扶養データ `number` と対応 |
| `在職` | 数値 | **在職判定** | 1 = 在職 |
| `氏名` | 文字列 | 印字 | 姓名は全角スペース区切り |
| `ﾌﾘｶﾞﾅ` | 文字列 | 印字（ふりがな欄がある場合） | 半角カナ。印字時は全角変換を検討 |
| `所属CD` / `所属名` | 数値 / 文字列 | 並び順・仕分け・印字 | 例: 1100 / 総務部総務課 |
| `係CD` / `係名` | 数値 / 文字列 | 並び順・仕分け・印字 | 例: 1100010 / 職員係 |
| `職名` | 文字列 | 印字 | 例: 主事 |
| `生年月日` | **Excelシリアル値** | （参考） | 下記5.4参照 |
| `採用日` / `退職日` | **Excelシリアル値** | 在職判定を厳密化する場合に使用 | 下記5.4参照 |
| `区分名` / `身分` / `職種` | 文字列 | 対象範囲の絞り込みに使う可能性 | 例: 正職員 / 一般行政職 |

### 5.3 扶養データ（21列）

| 列名 | 型 | 用途 | 備考 |
|---|---|---|---|
| `t_huyouid` | 数値 | レコード識別子 | |

### 5.4 日付の取り扱い（実装上の注意）

サンプルを解析した結果、**2ファイルで日付の持ち方が異なる**。

| ファイル | 列 | 実際の格納形式 |
|---|---|---|
| 名簿 | `生年月日` `採用日` `退職日` | **数値（Excelシリアル値）**、書式は General |
| 扶養 | `birthday` | 日付型（datetime） |

名簿側はシリアル値のため、**1900日付システム（基準日 1899-12-30）で日付に変換**する。

```
36602 → 2000-03-17
45017 → 2023-04-01
```

取込処理は「日付型ならそのまま／数値ならシリアル値として変換／文字列なら日付パース」の
3通りを受け付ける共通関数を用意する。空欄は NULL として扱う。

| `birthday` の欠損・変換不能 | 扶養 | エラー一覧。印刷対象外 |
| 名簿に該当 `番号` なし | 扶養 | 警告一覧。印刷対象外 |

### 5.6 サンプルデータの状況

現時点で提供を受けたサンプルは**各ファイル1行のみ**（名簿 `番号`=1007、扶養 `number`=1000）で、

## 6. 出力・印刷仕様

### 6.1 方式（v1.2で変更）

**サーバ不要の単一ページアプリ**。`index.html` をブラウザで開くだけで動作する。

当初（v0.2〜v1.1）は「ローカルでWebサーバを起動する」構成としていたが、
庁内PCへのランタイム（Python / Node.js）導入可否が確認できておらず、
それが実装のリスクとして残っていた。以下の理由から**サーバを立てない構成に変更した**。

| 論点 | 結論 |
|---|---|
| ランタイム導入 | **不要**。Edge だけで動くため導入可否の確認が要らなくなった |
| 配布 | フォルダごとコピーするだけ。インストール作業なし |
| 個人情報 | ブラウザ内で完結。ローカルサーバのポートすら開かないため、より安全 |
| Excel読み込み | SheetJS を `vendor/` に同梱（Apache-2.0）。CDN参照なし＝庁内ネットワーク制約の影響を受けない |

- 様式は HTML + CSS（`@page` / `size: A4` / `mm` 単位）で再現する
- 印刷はブラウザの印刷機能（Ctrl+P）を使用。「PDFとして保存」も可能
- 外部ネットワーク送信は行わない

### 6.2 印刷要件

- 対象者全員分を**1つのHTMLに連続出力**し、一括印刷できること
- 1件＝1ページとし、`page-break-after` でページを分割する
- 所属順・職員番号順に並べ、所属ごとの仕分けができること
- ブラウザのヘッダ・フッタ（URL、ページ番号）が出ない前提でレイアウトする旨を操作手順に明記
- 印刷プレビューと実印刷でズレが出ないよう、絶対単位（mm/pt）でレイアウトする

### 6.3 画面構成（実装済）

1ページ内を4セクションに分け、上から順に進める。

1. **条件とデータの読み込み** — 対象年度、名簿データ、扶養データを指定
2. **抽出結果** — 件数の集計と、エラー／警告／お知らせの一覧
3. **印刷対象** — 所属で絞り込み、職員単位でチェックして印刷対象を選ぶ
4. **印刷** — 調査書を人数分レンダリングし、そのまま印刷

印刷時は `@media print` で操作画面を非表示にし、調査書だけを出力する。

**対象年度は和暦のプルダウンで選択する**（v1.4で変更。当初は西暦4桁の数値入力だった）。

- 選択肢は当年度を基準に前後の年度を並べる（既定: 前2年度〜後3年度。
  `assets/config.js` の `fiscalYearRange` で変更できる）。過去年度分の再印刷にも対応する
- 表示ラベルは「令和8年度（2026）」のように和暦と西暦を併記する。
  西暦は人事給与システムの `year` 列と照合しやすいよう括弧書きで残した
- 内部的に保持する値（`Core.extract()` に渡す `fy`）は従来どおり西暦4桁のままで、
  3.1の抽出ロジックに変更はない。和暦化は表示層のみの変更である
- 元号の変換は `Core.fiscalYearLabel()` で行う。様式の日付欄の和暦表記（4.8、元年は「1」）とは
  別に、プルダウン表示では元年を「元」と表記する（画面表示としての読みやすさを優先）

### 6.4 CSV出力（v1.3で追加）

「印刷対象」画面に **一覧をCSV出力** ボタンを設け、対象扶養親族の一覧を
Excelで開けるCSVとして書き出せるようにした。職員係が名簿・監査資料として
別途一覧表を残しておきたい場合を想定している。

- 出力範囲は**表に表示されている行**（所属の絞り込みは反映する）。
  印刷用のチェックボックスの選択状態とは**独立**しており、チェックを外していても出力される
- 1扶養親族＝1行。同一職員に複数の扶養親族がいる場合は職員情報（所属名・職員番号・職員氏名）を
  行ごとに繰り返す
- 列: 所属名／職員番号／職員氏名／扶養親族氏名／生年月日（和暦）／生年月日（西暦）／
  年齢（基準日時点）／扶養手当月額（円）
  - 続柄は列コード表が未入手のため出力しない（4.6と同じ理由）
  - 扶養手当月額（`temp_kingaku`）は様式には印字しないが、人事給与システムの値を
    そのまま参照用に出力する
- 文字コードは **UTF-8（BOM付き）**、改行は **CRLF**。Excelで文字化けせず開ける形式とする
- ファイル名: `対象扶養親族一覧_{年度}年度.csv`
- ダウンロードはブラウザの標準機能（Blob URL）で行う。外部送信は行わない

## 7. 添付書類の要件（参考資料・本システムでは印字しない）

### 7.0 本システムでの扱い（v0.3で方針変更）

**本システムは添付書類に関する印字を一切行わない。**

理由: 受領した様式には**添付書類を記載する欄が存在せず**、注意事項1に
「添付資料は、各部課等の長宛の依頼文書を参照願います。」と記載されているため。
すなわち添付書類の案内は**調査書ではなく通知文書側の役割**である。

v0.2 で検討した「チェックボックス付き一覧の印字」は、様式に該当欄がないため**取りやめる**。

以下7.1〜7.6は、将来の拡張（就労証明書の印刷、回収時の確認リスト作成等）および
職員係の事務参照のために、通知【別紙】の内容を整理して残すものである。

通知【別紙】２⑶「添付書類 … 被扶養者資格確認調査と同じ。ただし、被扶養者資格確認調査と
重複している添付書類については添付の必要無し。」に基づき、別紙１⑸のルールを準用する。

### 7.1 全員

| 条件 | 添付書類 |
|---|---|
| 原則全員（無職無収入でも必要） | 所得証明書 |
| ただし**全日制の学校等の学生**は除く | — |

※「全日制の学校等」＝学校教育法に規定する学校、これに相当する海外の学校、
高校・大学等への入学を目的とした予備校。**定時制・通信制課程・夜間課程の学生等は要提出。**

### 7.2 収入がある場合

| 収入の内容 | 添付書類 |
|---|---|
| a 給与・報酬等 | 就労証明書（令和７年７月〜令和８年６月に1日でも就労していれば必要。様式を印刷し事業所から証明を受ける。**事業所の証明印の押印必須**） |
| b 年金 | 最新の年金改定通知書 又は 年金振込通知書の写 |
| c 事業収入（農業・自営業等） | 令和７年分の確定申告書及び収支内訳書の写 |
| d その他収入 | 当該収入を確認できる書類 |

### 7.3 18歳以上の全日制の学生（同居・別居とも）

- 在学証明書（令和８年４月１日以降交付のもの、**写不可**）

### 7.4 別居している場合

| 区分 | 添付書類 |
|---|---|
| a 全員（学生・施設入所者を除く。**定時制等の学生は要提出**） | 別居先世帯全員分の住民票／令和７年７月〜令和８年６月の各月の送金実績証明書（振込人・受取人の両方の氏名が記載されたもの。通帳の写等） |
| b 身体障害者授産施設、知的障害者更生施設、介護老人保健施設 入所者等 | 施設入所証明書の写 |
| c 養護老人ホーム、特別養護老人ホーム、児童福祉施設等 入所者 | 施設入所証明書の写／入所費用が確認できる書類／組合員が援助していることを客観的に証明できる書類（通帳の写等） |

### 7.5 組合員以外に優先扶養義務者がいる場合

（例: 母であれば父、孫であれば子 等）

- 優先扶養義務者の所得証明書
- 優先扶養義務者等の収入に関する証明書（収入がある場合）
- 世帯全員の住民票
  - ただし父母がともに被扶養者となっている場合、住民票は添付不要
  - 優先扶養義務者が後期高齢者医療制度の被保険者の場合、当該保険証の添付をもって住民票に代えられる

### 7.6 留意事項

- 事業所の倒産等により就労証明書が提出できない場合は申立書が必要（担当へ連絡）

### 7.7 参考: 自動判定が不可能である根拠

将来、添付書類の案内を自動生成する場合に備えて記録する。
提供を受けた扶養データ（21列）には、判定に必要な以下の情報が**いずれも存在しない**。

| 判定に必要な情報 | 扶養データでの有無 |
|---|---|
| 同居・別居の区分 | **なし**（様式でも職員が○をつける方式） |
| 収入区分（給与報酬／年金／事業／その他／無収入） | **なし**（`syotoku` 列はサンプルが空で用途未確認） |
| 学生区分（全日制／定時制・通信制・夜間） | **なし** |
| 施設入所区分（別紙の a / b / c） | **なし** |
| 優先扶養義務者の有無 | **なし** |

> 注意: `zei_doukyo` は列名から**税法上の同居老親等の判定フラグ**と推測されるが、
> これは所得税法上の概念であり、共済組合の被扶養者認定や扶養手当における
> 同居・別居の判定とは**別の概念**である。同居・別居の判定には流用しない。
> （`zei_doukyo` の正確な定義は未確認）
